## Blocking findings — `REVISE`

1. **CRITICAL — LIVE is neither QA-wallet-bound nor broadcast-denied.**

   The approved safety boundary requires simulator-container secret ingress,
   the expected QA sender comparison, and a transport-level deny guard before
   any LIVE observation. `iOS Example/Sources/Configuration.swift:14` reads
   `.env` from the process current directory; `iOS Example/Sources/Signing/LiveSendSession.swift:40-59`
   accepts any valid mnemonic, performs no expected-address/vector check, and
   constructs normal `Kit.instance`; the production factory installs the real
   broadcaster at `Sources/ThorChainKit/Core/KitFactory.swift:32-34,62-65`.
   There is no `BroadcastDenyingHTTPTransport` or count-only send/retry guard
   at this head, while `SendViewModel.swift:84-95` reaches `Kit.send`.

   A valid local mnemonic can therefore create a mainnet session and confirm a
   real broadcast, violating the slice's irreversible-send prohibition.

2. **HIGH — retry flow false-greens `sdk/19` and does not prove terminal retry.**

   `iOS Example/Sources/Signing/FixtureTransport.swift:163-189` returns a
   successful code `0` on the retry broadcast and never produces the required
   `sdk/19` response. `iOS Example/Sources/Send/SendViewModel.swift:40-43`
   fabricates the current fee as quoted fee plus one, while
   `iOS Example/Sources/Pending/PendingView.swift:20-30` hard-codes the text
   `sdk/19` before retry. `.maestro/sprint-02/send-retry.yaml:26-48` asserts
   that label before tapping Retry and does not assert terminal wording,
   disabled retry/replacement, or restart persistence.

   The required changed-fee acknowledgement and terminal CheckTx state are not
   exercised; the flow can display a protocol result it never received.

3. **HIGH — restart flow does not reuse its scenario namespace.**

   `.maestro/sprint-02/send-restart-pending.yaml:4-7` starts with
   `send-restart-pending`, but its second `launchApp` at lines 28-34 has no
   scenario argument. `ExampleRuntime.swift:230-242` then defaults the second
   process to `send-quote-review`, which selects a different persistence
   namespace. The before/after assertions target the always-present status
   label `PendingView.swift:9`, not a reconstructed transaction row.

   Empty `READY` state can satisfy both assertions without proving pending
   recovery or empty-versus-degraded behavior.

4. **HIGH — transcript completion can false-green after UI state publication.**

   `FixtureTranscript.finish()` fails closed at
   `iOS Example/Sources/Signing/FixtureTransport.swift:46-48`, but
   `SendViewModel.swift:147-152` discards quote-flow completion errors with
   `try?`, and send/retry publish success state before completion checking at
   lines 93-104 and 117-133. The new focused test uses a separate permissive
   broadcast transport (`Tests/ThorChainKitTests/KitCompositionTests.swift:221-278,333-358`)
   and does not exercise `FixtureScenario`/`FixtureTranscript`.

   An incomplete or extra transcript can therefore leave Maestro-visible state
   green while the strict fixture contract has failed.

5. **HIGH — the changed lifecycle account request accepts an arbitrary query.**

   `FixtureScenario.swift:60` declares the account request with `query == nil`;
   `FixtureTransport.swift:56` treats nil as a wildcard and the account branch

   `/cosmos/auth/v1beta1/accounts/<sender>?unexpected=value` is accepted,

6. **HIGH — runtime UI-tree and screenshot evidence can false-green.**
